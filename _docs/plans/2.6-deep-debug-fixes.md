# Muxmaster 2.6 — Deep-Debug Bug Fixes

**Status:** draft (no code changed; findings verified against current tree)
**Goal:** Fix the concrete correctness bugs surfaced by the 2.6 deep-debug pass —
data-loss in the post-encode escalation loop, title corruption in the naming
post-processor, batch-aborting discovery, the QVBR escalation dead-end, and the
unfinished `absolute.go` edge cases — without re-architecting the pipeline.
**Non-goals:** Calibration/measurement work, parallelism, new features, the
broad 2.7 theme. Where a fix overlaps 2.7's "A. Data-safety hardening" section it
is cross-referenced, not duplicated. No changes to the documented quality math
(planner QP/CRF invariants verified clean this pass).

## Context digest

A full deep-debug pass (build/vet/test/`-race` all green, 551 tests; five
parallel package audits) found the `planner` quality math, `probe`, `ffmpeg`,
`tune`, `config`, `check`, and `cmd` packages clean. The real defects cluster in
`pipeline` and `naming`, each reproduced before listing here:

1. **Post-encode escalation destroys a usable encode.** On size overshoot the
   loop `os.Remove`s the good output *before* the re-encode; if the re-encode
   fails/cancels, the file is reported failed with no output at all.
2. **Release-tag stripper eats real titles.** `MULTI`/`PROPER`/`BD`/`DD`/`NF` are
   dictionary words; `"Multi Tool"`→`""`, `"The DD Story"`→`"The"`.
3. **One unreadable directory aborts the whole batch** (`WalkDir` returns `err`).
4. **QVBR size escalation gates the wrong axis** — breaks on the QP ceiling while
   `-b:v` (the real size lever) never shrinks.
5. **`splitAbsolute` produces invalid episodes** (`E00`, unbounded `E746`) for
   out-of-range absolute numbers — unfinished `absolute.go`.
6. **Dashed vs dotted absolute forms diverge** — `Anime-dash` claims `- 253`
   before the absolute rule, so the season split silently doesn't apply.

Plus tooling/doc drift: `golangci-lint` not installed locally (`make ci`/`lint`
can't run); AGENTS.md `-max_interleave_delta` note is stale.

Lint note: `golangci-lint` must be installed and `make ci` must pass before this
plan is considered done — several fixes touch hot paths the linters cover.

## Ordered steps

Ordered by severity then risk. Steps 2, 3, 5, 6 are independent and low-risk;
do them first. Step 1 is the highest-impact change and overlaps 2.7-A1.

### Step 1 — HIGH: stop deleting the good output before the re-encode succeeds
*File:* `runner.go` (`executeWithRetry`, ~L390-432) and the caller (~L304-316).
*Bug:* line ~422 `os.Remove(plan.OutputPath)` runs before the escalation
re-encode; if `attemptWithErrorRetry` then returns `false` (ffmpeg error,
`ctx.Err()` on Ctrl-C, OOM), `executeWithRetry` returns `false` and the caller
removes the output again + `stats.Failed++` — a successfully encoded (merely
oversized) file becomes a hard failure with no output.
*Fix:* escalate against a temp path; keep the previous successful output as the
fallback and only replace it when a re-encode succeeds and is actually smaller.
Minimal form: encode each bump to `OutputPath + ".part"`, `os.Rename` over the
real path only on success; on bump failure/cancel keep the last good file and
return `true`. This is the local, scoped version of **2.7 plan A1** (atomic
encode-to-temp + rename) — if A1 lands first, this step folds into it; otherwise
implement the escalation-loop slice here and leave a `// see 2.7-A1` marker.
*Done-when:* a test drives a failing/cancelled re-encode after a successful
first pass and asserts the first-pass output still exists and the file is **not**
counted as `Failed`.

### Step 2 — MEDIUM-HIGH: stop the release-tag stripper from eating real titles
*File:* `postprocess.go` (`reReleaseTags`, L28-37; `stripReleaseTags`).
*Bug:* `MULTI|PROPER|BD|DD\+?|NF` are common words/initials; the function deletes
the first match and everything after it. Verified: `"Multi Tool"`→`""`,
`"Proper Noun"`→`""`, `"The DD Story"`→`"The"`, `"NF Game"`→`""`,
`"Cool BD Show"`→`"Cool"`.
*Fix (pick one):*
  - (a) Remove the dictionary-word/ambiguous tokens (`MULTI`, `PROPER`, `BD`,
    `DD`, `NF`) from the pattern — simplest, accepts these tags occasionally
    surviving in a title (rare, harmless).
  - (b) Keep them but only strip when the token sits adjacent to another known
    tag/resolution marker (e.g. require a following recognized tag), so a lone
    English word in a title is left intact.
  Prefer (a) unless the survived-tag cases matter; note the choice in the commit.
*Done-when:* table test asserts the five cases above keep their titles, and the
existing real-tag cases (`x264`, `1080p`, `BluRay`, `Dual.Audio`, …) still strip.

### Step 3 — MEDIUM: don't let one unreadable dir kill the batch
*File:* `discover.go` (`WalkDir` callback, ~L41-44).
*Bug:* callback returns `err` unconditionally, so a single permission-denied
subfolder aborts discovery of every readable file.
*Fix:* on a per-entry walk error, log a warning and continue — `return
filepath.SkipDir` when `d` is a dir, else `return nil`. Keep returning the error
only for a failure on the root input dir itself (nothing to process).
*Done-when:* test builds a tree with one `0o000` subdir and asserts readable
files are still discovered and the unreadable dir is logged, not fatal.

### Step 4 — MEDIUM: fix the QVBR escalation dead-end
*File:* `runner.go` (`executeWithRetry` VAAPI branch, ~L396-410).
*Bug:* in QVBR, output size is driven by `-b:v`, but the loop breaks on
`VaapiQP > VaapiQPMax`. Once QP is at 30 the loop exits and the bitrate target is
never shrunk, leaving a bloated QVBR output untouched.
*Fix:* decouple the QVBR break condition from the QP ceiling — when `VaapiQVBR`,
continue shrinking `OptimalBitrateKbps`/`MaxRateKbps`/`BufSizeKbps` by
`qvbrEscalateRetainPct` for the full `maxQualityBumps` regardless of QP (clamp QP
at max instead of breaking), and add a floor so the target can't shrink to 0.
*Done-when:* test with QVBR + QP already at max asserts the bitrate target
decreases across bumps (loop doesn't break immediately).

### Step 5 — MEDIUM: bound `splitAbsolute` to valid episode numbers
*File:* `absolute.go` (`splitAbsolute`, L80-89) + `absolute_test.go`.
*Bug:* `abs < starts[0]` → `episode 0` (`S01E00`, invalid Jellyfin token);
`abs` past the last boundary is unbounded (`"Dragon Ball Z 999"`→`S9E746` for a
291-ep show).
*Fix:* clamp the computed episode to `>= 1`; add an optional per-show
`episodeCount` (or `lastEnd`) bound so an out-of-range absolute number is
rejected (return a zero/`ParsedName{}` that lets the rule fall through to the
movie fallback) rather than emitting a garbage season/episode. Update the test
that currently codifies the `{0,1,0}` result.
*Done-when:* tests assert `abs=0`→fall-through (not `E00`) and an above-range
number falls through to the movie fallback instead of `S9E746`.

### Step 6 — MEDIUM (decision needed): reconcile dashed vs dotted absolute forms
*File:* `absolute.go` / `rules.go` ordering + `parser_test.go`.
*Bug:* absolute rules are spliced after `Anime-dash`, so `"Dragon Ball Z - 253"`
→ `S1E253` (no split) while `"Dragon.Ball.Z.253"` → `S8E34`. Same show/episode,
different result by separator.
*Decision:* confirm intent first —
  - If dotted/spaced-only is intended, leave ordering as-is and **document** it
    (comment in `absolute.go` + a guard test pinning the dashed form to its
    Anime-dash result so the divergence is intentional, not accidental).
  - If the season split should also apply to the common `- NNN` form, move the
    absolute rules **before** `Anime-dash` (the literal title anchor keeps them
    from over-matching) and add a dashed-form test.
*Done-when:* the chosen behavior is covered by an explicit test and a one-line
rationale comment; no silent separator-dependent divergence remains.
