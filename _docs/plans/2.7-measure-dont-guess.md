# Muxmaster 2.7 — "Measure, Don't Guess"

**Status:** draft (tentative; research-grounded, no code changed)
**Theme:** Replace the uncalibrated static QP apparatus with *measurement* —
first an on-box calibration harness, then opt-in per-content quality targeting —
and fix the data-safety/correctness bugs that make the current pipeline unsafe
to trust on a real library. Parallelism is explicitly out of scope (single-GPU
box; serial is correct).

---

## Context digest

2.6 shipped a "quality-first" per-file QP model, but a deep review found its
headline feature is **mathematically inert** in the common cases and every
quality magnitude is an admitted placeholder hardcoded to one box (Radeon 680M /
VCN 3.1):

- Grain QP is pinned by a constant collision (`vcnQPCeilingGrain == vcnContentClassMinGrain == 22`,
  [quality.go](../../internal/planner/quality.go)) — the whole curve/bias stack is dead math for grain.
- The clean ceiling (`vcnQPCeilingClean = 16`) is unreachable because
  `boundedPushQP = max(baseQP, min(targetQP, ceiling))` and baseQP > 16 almost always.
- `PreflightAdjust` ([estimation.go](../../internal/planner/estimation.go)) then *overrides* whatever
  survived (the self-flagged `TODO(Change 6)`), so output is governed by a size-shrink — the
  opposite of the stated intent — driven by the `vaapiRatios` table that is itself
  "a withdrawn heuristic, not measured data" ([tables.go](../../internal/planner/tables.go)).

Research (2026-06-13, adversarially verified) settled the path forward:

1. **The ab-av1 sample-encode → measure → interpolate loop transfers to
   `hevc_vaapi` CQP** (ab-av1 already supports `-e hevc_vaapi`, substituting
   integer `-qp` for CRF). ~5–10% encode-time overhead via short samples. The
   real limiter is QP being integer/coarse, not the concept.
2. **VMAF is actively wrong for this project's two dominant content types.** It
   over-scores flat/dark anime (banding hidden) and is gameable/unreliable on
   film grain. **Trap:** measuring a *denoised* encode against the *grainy
   original* makes VMAF punish the denoiser and push QP down, wasting bits —
   the metric fights the pipeline. Mitigations: reference against the **denoised
   intermediate**, use **VMAF-NEG**, prefer **SSIMULACRA2/XPSNR** for
   detail/banding. No per-frame metric judges grain-in-motion — keep a spot-check.
3. **Hardware reality confirms the memory.** On VCN 3.1: HEVC B-frames are
   permanently hardware-gated off; `denoise_vaapi` unimplemented on radeonsi;
   radeonsi HEVC exposes **CQP/CBR/VBR only — not QVBR**; `compression_level`
   inert. AV1 encode and real B-frames begin at VCN 4/5. So on the dev box the
   entire quality story stays **CQP + software-decode denoise**; everything else
   is forward-looking and must be **per-VCN-generation gated**.

Net thesis: the project's value proposition rests on numbers it never measured.
2.7 makes the numbers real (on whatever box the user runs), pays down the
calibration debt by *retiring dead apparatus rather than calibrating it*, and
hardens the pipeline against the data-loss paths.

---

## Goals

- Make every quality constant **measured on the user's actual hardware**, not
  hardcoded to the 680M, via a built-in calibration harness.
- Offer an **opt-in per-content quality-target encode** (ab-av1-style QP search)
  that is structurally correct (smallest size at a quality floor) and needs no
  tables — defaulting OFF so current behavior is byte-identical when unused.
- **Retire the inert bounded-push / preflight-fight apparatus**, replacing it
  with either the measured tables (default fast path) or the search (opt-in).
- Close the **data-safety holes** (non-atomic writes, stale-skip, dup overwrite)
  and the concrete correctness bugs (`-vf` cover-art, retry off-by-one, flag
  conflicts).
- Add a **per-VCN-generation capability model** so the tool stops assuming one
  GPU and can light up AV1 (VCN 4+) without regressing VCN 3.1.

## Non-goals

- Parallel/concurrent file encoding. Out of scope by decision.
- Per-shot convex-hull optimization (Netflix dynamic optimizer). The convex-hull
  *mental model* informs the design; full per-shot is overkill for a muxing CLI.
- Auto-detecting anime vs live-action (research-settled: no reliable classifier;
  stays a per-series user prompt).
- Flipping the default off CQP. CQP stays the quality-first default on AMD.
- Mandatory metric dependency. The tool must still run with no VMAF/SSIMULACRA2
  available — calibration and targeting are opt-in, with graceful fallback to
  the shipped default tables.

## Workstreams

Ordered by priority. A ships independently and first (pure hardening, low risk).
B is the spine. C is the ambitious payoff and depends on B. D is forward-looking.

### A. Data-safety & correctness hardening (must-fix, low risk, ship first)

Files: [internal/pipeline/runner.go](../../internal/pipeline/runner.go),
[internal/ffmpeg/builder.go](../../internal/ffmpeg/builder.go),
[internal/ffmpeg/executor.go](../../internal/ffmpeg/executor.go),
[internal/ffmpeg/retry.go](../../internal/ffmpeg/retry.go),
[internal/config/flags.go](../../internal/config/flags.go),
[internal/config/config.go](../../internal/config/config.go),
[Makefile](../../Makefile).

- **A1. Atomic encode-to-temp + rename.** Encode to `output.mkv.part` (same
  filesystem), `os.Rename` on success, `os.Remove` the temp on any
  failure/cancel. Cleanup co-located with the cancellation detection in
  `attemptWithErrorRetry`, not scattered in the caller. Fixes: crash/OOM/full-disk
  corruption at the final path, in-place clobber of a good prior output, and the
  stale-skip footgun in one stroke.
- **A2. Graceful subprocess shutdown.** Set `cmd.Cancel` + `cmd.WaitDelay`
  (SIGTERM then SIGKILL) on the `exec.Cmd` so ffmpeg can finalize; consider
  `Setpgid` to avoid orphaned helpers. Remove the `os.Exit(1)` on second SIGINT
  in `main.go` in favor of a path that still runs `defer log.Close()` /
  temp cleanup.
- **A3. `-vf` → `-filter:v:0`.** Scope the prefilter chain to the primary video
  stream so it doesn't collide with `-c:v:N copy` cover-art maps (currently
  builds an invalid command for any encode of a file with embedded cover art).
- **A4. Retry budget + cap.** Fix the off-by-one so all 7 fix classes can fire
  (increment after the limit check, or `MaxAttempts = classes + 1`). Add a hard
  loop-iteration cap in `attemptWithErrorRetry` as defense-in-depth independent
  of `Advance`'s one-way booleans.
- **A5. Flag-conflict validation.** Reject (or warn + define precedence
  explicitly) `--quality-priority` + `--size-priority`, `--color` + `--no-color`,
  `--smart-quality` + `--no-smart-quality` in `Config.Validate()` instead of
  silently resolving. Prefer collapsing quality/size priority into one enum.
- **A6. Skip-existing validity check.** Gate the `os.Stat` skip on a cheap
  integrity signal (nonzero size + ffprobe duration ≈ source), not bare
  existence, so an interrupted-run partial isn't treated as done. (A1 makes
  partials never land at the real path, but keep this as belt-and-suspenders.)
- **A7. Single CollisionResolver.** Remove the duplicate resolver instance in the
  auto-tune candidate pass; resolve once and share, so candidate-pruning and the
  encode loop can never assign divergent dedup suffixes / series names.
- **A8. Tests for the untested risk surface.** Behavioral tests driving a
  *failing* ffmpeg through the retry loop (classification + `os.Remove` + re-run),
  `ffmpeg.Execute` itself, and `processFile` failure/cleanup paths (probe fail,
  mkdir fail, output-larger escalation). These are currently 0%-covered and are
  the only places the tool can destroy data.
- **A9. Makefile drift.** Update the `docs-naming` allowlist (it points at a
  deleted plan file and now flags the real plan docs).

**Done-when (A):** interrupt/crash mid-encode never leaves a file at the final
path; `make test` covers a failing-ffmpeg retry cycle; conflicting flags error;
`make ci` green.

### B. The measurement harness (spine)

New package: `internal/quality/` (metric runners + curve model). New subcommand
`muxmaster calibrate`. Touch: [internal/planner/tables.go](../../internal/planner/tables.go),
[internal/planner/quality.go](../../internal/planner/quality.go),
[internal/tune/suggest.go](../../internal/tune/suggest.go).

- **B1. Metric runners.** `libvmaf` via ffmpeg as the default workhorse (in-tree,
  CPU, bounded 0–100, trivial to target). **Use VMAF-NEG, not default VMAF.**
  Add `XPSNR` (in-tree ffmpeg filter) as a cheap grain/banding cross-check.
  Optional `SSIMULACRA2` via FFVship when present (capability-gated: needs ROCm
  or the experimental Vulkan build on AMD — never required). All comparisons
  reference the **denoised intermediate** when a prefilter is active, so the
  metric never punishes the denoiser.
- **B2. `muxmaster calibrate [LIBRARY]`.** Sample N short clips spanning the
  user's content classes/resolutions, sweep `-qp` across the usable range on the
  *real selected encoder*, measure (qp → quality, size) per class, and write a
  versioned `calibration.json` (keyed by detected GPU/VCN gen + ffmpeg/Mesa
  version). This is the one-time, dev-or-user-side step the whole 2.6 design was
  waiting on — now reproducible per box instead of hardcoded.
- **B3. Load measured curves; demote placeholders to fallback.** `tables.go`
  and the `vcnQPCeiling*` / grain-threshold constants read from `calibration.json`
  when present, else fall back to the current placeholders (clearly labeled
  "uncalibrated default"). This is how the calibration debt is actually paid:
  the magic numbers become data, and the dead `boundedPushQP`/preflight conflict
  is resolved against *measured* curves instead of a withdrawn heuristic.

**Done-when (B):** `muxmaster calibrate` on the dev box emits a `calibration.json`
whose grain knee/ceilings match the memory's measured ~24–26 knee; the planner
consumes it; running without it reproduces 2.6 output exactly.

### C. Per-content quality targeting (opt-in payoff; depends on B)

Files: [internal/pipeline/autotune.go](../../internal/pipeline/autotune.go)
(reuse per-series grouping), [internal/planner/planner.go](../../internal/planner/planner.go),
new `internal/quality/search.go`.

- **C1. `--target-quality <metric=score>` mode.** Per series (reusing the
  existing autotune series grouping and once-per-series prompt), run an
  ab-av1-style QP search on a representative sample: encode at a few QPs, measure,
  interpolate, pick the **lowest QP (smallest size) that clears the floor**, then
  apply that QP to every episode. Cache per-series results. Default OFF.
- **C2. Retire the inert apparatus.** When targeting is on, bypass the §2b
  upward push and `PreflightAdjust` entirely — the measured QP governs; keep only
  the "never exceed input size" safety net. When off, collapse the two-stage
  push-vs-preflight fight (they optimize different statistics and undo each other)
  into a single bounded step driven by B's measured curves.
- **C3. Calibrated grain detection.** Replace the placeholder
  `grainLightThreshold` / `grainHeavyThreshold` cut points and `hqdn3d`
  strengths with values fit from B1, and improve sampling robustness
  (multi-window + percentile instead of a single 24 s mean, per the review) so a
  per-series grain call isn't decided by one low-grain stretch.

**Done-when (C):** `--target-quality vmaf_neg=95` produces, for a sample set,
encodes at-or-just-above the floor with smaller size than the 2.6 default at
equal measured quality; default-off runs are unchanged.

### D. Per-VCN-generation capability model (forward-looking, hardware-gated)

Files: [internal/check/check.go](../../internal/check/check.go),
[internal/config/config.go](../../internal/config/config.go),
[internal/ffmpeg/builder.go](../../internal/ffmpeg/builder.go).

- **D1. Detect VCN generation** (from PCI id / driver), not just vendor. Gate all
  vendor-specific quality magnitudes and feature paths on it.
- **D2. Reconcile the AMD QVBR path.** Research says radeonsi HEVC exposes no
  QVBR (CQP/CBR/VBR only), yet 2.6 has a QVBR opt-in and a measured "QVBR loses
  to CQP" result. Verify what `--vaapi-rc qvbr` actually selects on radeonsi;
  either fix the capability gate or remove the dead AMD QVBR path.
- **D3. `av1_vaapi` encoder path**, opt-in, gated to **VCN 4+** detection — never
  offered on the 680M. Foundation only; quality tuning for AV1 is a later
  milestone.
- *(B-frame probe already verifies `pict_type=B` per AGENTS.md — no action.)*

**Done-when (D):** the tool reports detected VCN generation in `--check`; AV1 is
offered only on VCN 4+; no dead QVBR path remains on AMD.

## Risks & open questions

- **Integer QP is coarse.** A VMAF/SSIMULACRA2 target may land between two QP
  steps; the search must pick "best integer clearing the floor," accepting it
  won't hit a target precisely. Document this; don't over-promise precision.
- **Metric trust on grain/anime.** Even with VMAF-NEG + denoised-reference, no
  per-frame metric judges grain-in-motion. The quality floor must be validated
  against the owner's own A/B viewing, not a blog's "95 = transparent" convention.
- **Calibration sample representativeness.** A bad sample set yields bad curves;
  `calibrate` should report per-class sample counts and refuse to overwrite the
  fallback on thin data.
- **SSIMULACRA2 on AMD is not turnkey** (ROCm finicky, Vulkan build experimental).
  VMAF-NEG via libvmaf is the committed default; SSIMULACRA2 stays optional.
- **Scope.** A+B is a coherent, shippable 2.7 on its own ("measured tables +
  hardened pipeline"). C and D can slip to 2.8 if needed — structure the work so
  A and B don't depend on them.

## Suggested sequencing

1. **A** (hardening) — independent, de-risks everything, ship as 2.7.0-beta.
2. **B** (harness + measured curves) — the spine; turns the design honest.
3. **C** (opt-in targeting) — the payoff, once B's metrics exist.
4. **D** (VCN-gen model + AV1 foundation) — forward-looking, parallel to C.
